# draft-proposal

`brief → LLM → proposal.typ → PDF`

A one-line brief becomes a structured PDF proposal. The LLM fills the
template's slots; the template itself (`../templates/proposal.typ`) is
immutable per run — signature block, layout, and boilerplate stay
identical across every proposal.

## Why the template is the load-bearing part

- LLM-drafted documents drift in style and miss legal/brand
  boilerplate. Forcing every proposal through `proposal.typ` keeps the
  signature block, register entry, and disclaimer **byte-identical**
  across runs.
- The LLM only generates the FIELD VALUES (title, summary, scope items).
  It cannot rearrange the document.
- Reviewing a proposal becomes "did the LLM understand the brief?"
  not "is the template wrong this time?"

## Use it

```bash
# Setup once
pgf connect llm local         # or any OpenAI-compatible endpoint

# Draft
./draft.sh "Migrate Acme Corp from Magento to Shopify; 3 phases over 2 months; 60k EUR fixed-fee" /tmp/acme-proposal.pdf
```

Output: `/tmp/acme-proposal.pdf`. Inspect, edit `proposal.typ` if the
layout needs work, re-run.

## Customise

Three env vars override the fixed signature block:

```bash
PROPOSAL_AUTHOR="..." \
PROPOSAL_COMPANY="..." \
PROPOSAL_CONTACT="..." \
./draft.sh "<brief>" out.pdf
```

For real corporate use, edit `../templates/proposal.typ` to use your
typography, logo, footer. The LLM doesn't see the template — it just
fills the JSON.

## Trust profile

| Field | Generated by |
|---|---|
| `title`, `summary`, `scope`, `deliverables`, `timeline`, `pricing` | LLM |
| `date` | LLM, but anchored to "today is $(date +%Y-%m-%d)" in the system prompt |
| `author`, `company`, `contact`, signature block | env / fixed in template |
| Layout, fonts, footer | `proposal.typ` (committed to git) |

**Always review before sending.** This is an automated *first draft*,
not finished output.

## Prereqs

- pgf with an `llm` instance (`pgf connect llm local`)
- `typst` on `$PATH`
- `jq`
